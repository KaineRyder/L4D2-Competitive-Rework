Download and install SteamCMD before installing the server.<br>>   <br>> <br>>  Example Windows .bat file to **install and update** a CS:GO server. Good Coding Practices:**<br>- Use **RemoveEntity(entity);** (in SM 1.10+) which is a faster and safer version of **AcceptEntityInput(entity, "Kill");** (in SM <= 1.9) instead of RemoveEdict(entity).<br>  <br>  <br>\- RemoveEdict in some cases can be safe and good for creating + deleting an entity in a single function when you only briefly need it, e.g. point\_hurt and env\_shake.<br>  <br>  <br>\- RemoveEdict is known to crash the server, when used with certain entities or at the wrong time, e.g. when deleting a weapon that's equipped on a player.<br>  <br>- Before using or killing an entity, ensure it is valid with **IsValidEntity();**<br>  <br>  <br>\- Necessarily check for zero if(entity != 0) or just if(entity), because 0 (on dedicated server) is a world and valid, so you can crash server instantly.<br>  <br>- No sense in using if **IsClientConnected(client) && IsClientInGame(client)** together since **IsClientInGame** already includes **IsClientConnected** check.<br>  <br>- Use uniform style for naming the variables. Good start is " [Hungarian notation](https://en.wikipedia.org/wiki/Hungarian_notation)"<br>  <br>  <br>\- e.g. prepend g\_ if variable is declared in global scope.<br>  <br>- Use **TIMER\_FLAG\_NO\_MAPCHANGE** to close timer handles automatically when the map ends. Does not close on round\_end event only map change (OnMapEnd).<br>  <br>  <br>\- It prevents from unexpected consequences.<br>  <br>  <br>\- **Unless** you are storing the handle and manually killing the timer, in which case you would receive "Exception reported: Invalid timer handle". See [details on timers here](https://forums.alliedmods.net/showpost.php?p=2688863&postcount=33).<br>  <br>- **!!** iValue - to convert " **int**" to " **bool**"<br>  <br>- I personally declare " **char**" variables as " **static char**" if they are large and called multiple times in expensive loops or Think\* functions.<br>  <br>  <br>\- This will optimize speed, because the variable is not allocated multiple times. **BUT:** This memory is never destroyed and always there.<br>  <br>  <br>\- Only use if you understand what you're doing. This is only really beneficial for expensive functions and high tick servers with 50-100+ crazy plugins where optimizing becomes necessary.<br>  <br>  <br>\- However: **"using static for local arrays isn't good advice, it leads to many bugs and stack allocation is cheap."** \- asherkin.<br>  <br>- If you want assign the same value to all array items you can do it during initializing rather then in a loop later: **int test\[32\] = {1, ...};**<br>  <br>  <br>\- Otherwise **int test\[32\]** fills the array with the default value, 0 in this case.<br>  <br>- **TeleportEntity** before **DispatchSpawn**. Doing the other way round can cause the server to crash. Happens with some models/entity types spawning at 0,0,0.<br>  <br>- **switch** instead of multiple **if else** statements. This is probably faster too. More [info here](https://wiki.alliedmods.net/Introduction_to_SourcePawn#Switch_Statements).<br>  <br>  <br>\- **case** section uses constant values. It can also support multiple values e.g. **case 1,2:**<br>  <br>- **c\[0\] == 'a'** instead of full string comparisons, e.g. when checking a list of known player models. Find an index in the string where each character is unique. Can also use **switch()**.<br>  <br>  <br>\- Good example by Lux can be [found here](https://github.com/LuxLuma/-L4D2-Survivor_Legs/blob/master/_%5BL4D2%5DSurvivor_Legs.sp#L510-L587).<br>  <br>- **strcmp** instead of **StrEqual**. The latter is simply a wrapper to the former and slower by creating an extra call.<br>  <br>- **StrContains** \- This should only be used if you really don't know the position of something in a string. It's better to use **strcmp** or **strncmp** if you know the string you want to check. WIth the latter you can do partial matching and even into the char array for example: checking **char weapon\[64\] = "weapon\_rifle\_m60"**<br>  <br>  <br>to match any "rifle" you can do **strncmp(\[weapon\[7\], "rifle", 5)**. Another alternative is **FindCharInString** if you want to find the first occurrence of a character (option to check from end of string too).<br>  <br>- **FormatEx** instead of **Format**. When input and output buffers are NOT the same.<br>  <br>- Doing **FormatEx(blah, sizeof(blah), "%s", someStr);** is only very very slightly quicker than **IntToString(i, blah, sizeof(blah));** but basically no comparison so use any.<br>  <br>  <br>\- Both however are 3x to 10x quicker than doing **Format(blah, sizeof(blah), "%d", i);**<br>  <br>- **StringMap.GetValue** is slightly quicker than **ArrayList.FindString** and probably significantly faster for larger arrays.<br>  <br>- Preference **SDKHook\_Think** and similar functions over using **OnGameFrame**.<br>  <br>- Create one timer for all players instead of separate timer for each one (example: HP regen plugins).<br>  <br>- **delete** and **null** are preferred over **CloseHandle** and **INVALID\_HANDLE**. **delete** also sets the handle to null so you don't have to.<br>  <br>- Storing cvar handles, using [HookConVarChange](https://sm.alliedmods.net/new-api/convars/HookConVarChange) and storing the returned cvar values in global variables is more efficient than constantly using GetConvar\* calls.<br>  <br>  <br>\- See any number of my plugins for examples.<br>  <br>- Use **%N** instead of **GetClientName()** where possible, e.g. when using **Format**.<br>  <br>- You only need to put the keyword **public** before forwards from SourceMod and forwards from 3rd party plugins. Callbacks that you name yourself don't need "public" in front of them, for example `CreateTimer`, `HookEvent`, `RequestFrame` and other manually named callbacks.<br>  <br>- **Late Loading** \- More The latter is from older scripts before the former function was added.<br>  <br>- Using `strlen` to check if a string is empty. Debugging Plugins:**<br>> Info by Dragokas:<br>- Check `addons/sourcemod/logs/error_<date>.log` constantly; the most important parts are - error description (often omitted by users when they ask for help) and line number.<br>  <br>- Most direct and fastest method for resolving plugin conflicts or finding problem plugins is by - halving, by removing half of the plugins -> test -> repeat again.<br>  <br>- Install [Accelerator Extension](https://forums.alliedmods.net/showthread.php?t=277703) (works best on Linux) which provides various debugging information when a server crashes.<br>  <br>- Use -debug switch in servers startup [command line parameters](https://developer.valvesoftware.com/wiki/Command_Line_Options) to get more detailed description in crash logs.<br>  <br>- Memory leaks can be found by using `sm_dump_handles handles.txt` and studying the result. Also good consolidator: [https://hexer10.github.io/Sourcemod-HandleDumpParser/](https://hexer10.github.io/Sourcemod-HandleDumpParser/)<br>  <br>  <br>Pay attention to entries with too many handles, like > 50 (except forwards), instead of total memory they used like some people think, unless you are the author to be able make such a conclusion.<br>  <br>- In that case it's better to compare memory by timeline to understand is it a leak:<br>  <br>  <br>Little explanation - make dump #1, wait till map end, make dump #2, change map, make dump #3; restart server, make dump #4, compare most suspicious values between dumps to see how memory/handle count increasing by time. In most cases, they should not, or should in a very limited range.<br>  <br>- Use [ac\_debug](https://forums.alliedmods.net/showpost.php?p=2682433&postcount=16) plugin (see attached in links post) to measure performance of each plugin using valve profiler (not working in L4D1/L4D2 at the moment).<br>  <br>- [LogStackTrace](https://sm.alliedmods.net/new-api/sourcemod/LogStackTrace) function - Useful to write the last chain of function calls to error log. **Basics:**\
\
\- floating point operations specific, like:\
\
incorrect:\
\
PHP Code:\
\
`\
\
float f = 1.5;\
int i = 2;\
i += f;\
PrintToServer("wrong: %i", i); // Answer: 1080033280\
\
`\
\
correct is to cast float to int first using rounding:\
\
PHP Code:\
\
`\
\
float f = 1.5;\
int i = 2;\
i += RoundToCeil(f); // or RoundToFloor, RoundToZero, RoundFloat, RoundToNearest\
PrintToServer("correct: %i", i); // Answer: 4\
\
`\
